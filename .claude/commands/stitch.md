Прочитай:
- `outputs/prd.md` — одностраничный PRD продукта (результат Урока 1).

Собери Stitch-промпт по структуре ниже. Это промпт, который пользователь скопирует целиком в Google Stitch для генерации серии экранов в едином стиле.

## Структура промпта на выходе

Сохрани в `outputs/stitch_prompt.md`:

```
# Stitch Prompt: [Название продукта из PRD]

## Контекст продукта
[Одно-два предложения из секции «Что это» PRD — суть продукта и ЦА.]

## Визуальный язык
[2-3 предложения о тоне бренда: настроение (спокойный / энергичный / утилитарный), ключевые образы, основные цвета если уже понятны.]

## Экраны для генерации
Сгенерируй [N] связанных экранов в едином стиле. Каждый экран — отдельный артборд.

### Экран 1: [Название]
- Назначение: [что пользователь здесь делает]
- Контент: [перечисление ключевых элементов]
- **Слоты под визуал** (оставь пустыми placeholder-зонами):
  - Hero-зона под иллюстрацию (если применимо)
  - Плейсхолдеры под иконки фич
  - Фоновый блок под паттерн
  - Область под логотип в шапке

### Экран 2: [Название]
...

### Экран 3: [Название]
...

## Технические требования
- Чистые редактируемые слои при экспорте в Figma.
- Сетка 8 px.
- Единая типографика на всех экранах.
- Все placeholder-зоны под визуал — отдельными слоями с понятными именами (Hero_Placeholder, Icon_Slot_1, Pattern_Background и т.д.).
```

## Правила сборки

- Возьми **3-5 ключевых экранов** из «Скоп MVP» PRD — те, что отмечены Must.
- Для каждого экрана собери список контента из секции «Ключевые сценарии».
- Слоты под визуал добавляй везде, где макет визуально пустой: hero, иконки, паттерны, иллюстрации. Это критично — без них Урок 3 (бренд-пак) не сможет вставить ассеты.
- Не выдумывай элементы, которых нет в PRD. Если данных не хватает — оставь `[уточнить: что]` и в конце вывода перечисли что нужно уточнить.
